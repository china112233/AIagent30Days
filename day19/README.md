# Day 19: 其他框架探索

## 概述

在深入学习了 LangChain/LangGraph 和 LlamaIndex 之后，本天将探索其他几个重要的 LLM 应用开发框架：Semantic Kernel、Dify 和 AutoGen。这些框架各有特色，代表了不同的设计理念和应用场景，了解它们可以帮助我们在实际项目中做出更好的技术选型决策。

## 学习目标

- 理解 Semantic Kernel 的"技能"概念和插件架构
- 了解 Dify 低代码平台的特性和集成方式
- 掌握 AutoGen 多 Agent 对话框架的工作原理
- 比较各框架的优劣势和适用场景
- 为实际项目技术选型提供参考

| 特性 | Semantic Kernel | Dify | AutoGen |

| **RAG 支持** | 基础 | 强大 | 基础 |
| **部署方式** | 代码集成 | 云平台/自部署 | 代码运行 |

### 4. Semantic Kernel 技能类型

| 技能类型 | 说明 | 示例 |
|----------|------|------|
| **Semantic Function** | 基于提示模板的语义函数 | `{{input}} -> {{output}}` |
| **Native Function** | 代码实现的原生函数 | Python 函数、API 调用 |
| **Skill** | 多个函数的组合 | 数据处理技能包 |
| **Planner** | 自动规划执行计划 | SequentialPlanner |

```bash
# AutoGen 代码执行配置
AUTOGEN_CODE_EXECUTION=true
```

## 最佳实践

### 1. Semantic Kernel 技能设计

```python
# ✅ 好的技能设计：清晰的语义函数
from semantic_kernel import SKContext

# 使用语义函数模板
skill = kernel.create_semantic_function(
    "Translate",
    "将以下文本翻译为{{target_language}}：\n{{input}}",
    max_tokens=100
)

# ❌ 避免：过于复杂的单一函数
# 应拆分为多个简单技能，便于 Planner 组合
```

## 常见问题

| 问题 | 框架 | 原因 | 解决方案 |
|------|------|------|----------|
| 技能执行失败 | SK | 参数类型不匹配 | 检查 SKContext 变量绑定 |
| Planner 无计划 | SK | 技能描述不清 | 优化技能的语义描述 |
| Dify API 401 | Dify | API Key 错误 | 检查 DIFY_API_KEY 配置 |
| 工作流超时 | Dify | 节点过多 | 简化流程或增加超时设置 |
| Agent 无响应 | AutoGen | LLM 配置错误 | 检查 llm_config 的 model |
| 代码执行失败 | AutoGen | 沙箱配置问题 | 确认 work_dir 存在且可写 |
| 对话无限循环 | AutoGen | 缺少终止条件 | 设置 max_round 或终止消息 |

## 框架选型指南

### Semantic Kernel 适用场景

- 企业级应用开发
- 需要与微软生态集成（Azure、Power Platform）
- 强调技能复用和模块化
- 需要自动规划和编排

### Dify 适用场景

- 快速原型验证
- 非技术人员参与开发
- 可视化流程设计需求
- 开箱即用的知识库功能

### AutoGen 适用场景

- 多 Agent 研究和实验
- 复杂问题需要多角度讨论
- 代码生成和自动执行
- 学术研究和算法探索

## 框架组合建议

| 组合方式 | 适用场景 | 说明 |
|----------|----------|------|
| Dify + 自定义代码 | 生产应用 | Dify 做前端，后端用 Python 扩展 |
| AutoGen + LangGraph | 研究 + 生产 | AutoGen 做实验，LangGraph 做部署 |
| Semantic Kernel + Azure | 企业应用 | 利用 Azure 云服务集成优势 |
