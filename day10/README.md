# Day 10: RAG 基础 - 检索增强生成

## 概述

第十天学习 RAG (Retrieval-Augmented Generation，检索增强生成)，这是解决大模型知识局限性的核心技术。通过 RAG，我们可以让模型访问私有数据、获取最新信息、减少幻觉，构建更可靠的知识密集型应用。

## 学习目标

- 理解 RAG 的核心原理和架构
- 掌握向量数据库的使用方法
- 学会文档切分和嵌入策略
- 实现完整的 RAG 系统
- 了解 RAG 的优化方向

### 3. RAG vs 微调

| 特性 | RAG | 微调 (Fine-tuning) |
|------|-----|-------------------|
| 知识更新 | 实时更新 | 需要重新训练 |
| 数据隐私 | 数据留在本地 | 数据进入模型 |
| 成本 | 较低 | 较高 |
| 适用场景 | 知识密集型任务 | 特定领域任务 |
| 可解释性 | 高（可引用来源） | 低 |
| 幻觉控制 | 较好 | 一般 |

```
选择建议：

┌─────────────────────────────────────────────────────────────┐
│                      选择 RAG 当：                           │
├─────────────────────────────────────────────────────────────┤
│ ✅ 需要访问最新或动态数据                                    │
│ ✅ 数据频繁更新                                              │
│ ✅ 需要引用数据来源                                          │
│ ✅ 数据隐私要求高                                            │
│ ✅ 预算有限                                                  │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                     选择微调 当：                            │
├─────────────────────────────────────────────────────────────┤
│ ✅ 需要改变模型的行为方式                                    │
│ ✅ 特定领域的专业任务                                        │
│ ✅ 需要极低的延迟                                            │
│ ✅ 数据相对稳定                                              │
│ ✅ 有充足的训练资源                                          │
└─────────────────────────────────────────────────────────────┘
```

### 5. 文档切分策略

```python
# 1. 固定长度切分
"""
按固定字符数或 Token 数切分
优点：简单、可控
缺点：可能截断语义
"""

# 2. 递归字符切分
"""
按分隔符层级递归切分：段落 → 句子 → 词
优先保持语义完整性
推荐用于大多数场景
"""

# 3. 语义切分
"""
基于语义相似度切分
使用嵌入模型计算句子相似度
相似度低时切分
"""

# 4. 滑动窗口
"""
有重叠的切分方式
保持上下文连续性
"""

# 切分参数示例
chunk_size = 500      # 每块大小
chunk_overlap = 50    # 重叠大小
```

**切分策略选择：**

| 文档类型 | 推荐策略 | 原因 |
|----------|----------|------|
| 技术文档 | 递归字符 | 保持代码块完整 |
| 问答对 | 按问答对 | 保持问答完整 |
| 长文章 | 语义切分 | 保持段落完整 |
| 法律文件 | 固定长度 + 滑动窗口 | 确保关键条款完整 |

### 6. 向量数据库对比

| 数据库 | 类型 | 特点 | 适用场景 |
|--------|------|------|----------|
| **Chroma** | 本地 | 轻量、易用、开源 | 开发测试、小规模应用 |
| **Pinecone** | 云服务 | 托管、高性能、易扩展 | 生产环境、中大规模 |
| **Milvus** | 开源/云 | 高性能、可扩展、功能丰富 | 大规模、企业级 |
| **Weaviate** | 开源/云 | 语义搜索、混合检索 | 知识图谱、复杂检索 |
| **FAISS** | 本地库 | Meta 开源、高性能 | 本地部署、高性能需求 |
| **Qdrant** | 开源 | Rust 实现、高性能 | 自托管、生产环境 |

```
选择建议：

开发阶段 ──→ Chroma（快速上手）
生产环境 ──→ Pinecone（免运维）或 Milvus（自托管）
大规模数据 ──→ Milvus / Qdrant
本地部署 ──→ Chroma / FAISS / Qdrant
```

## 使用示例

### 基础用法

```python
from rag_engine import RAGEngine
from document_processor import DocumentLoader, TextSplitter

# 创建 RAG 引擎
rag = RAGEngine(
    embedding_model="text-embedding-3-small",
    vector_store="chroma"
)

# 加载文档
loader = DocumentLoader()
documents = loader.load("documents/")

# 切分文档
splitter = TextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split(documents)

# 构建索引
rag.index(chunks)

# 查询
response = rag.query("什么是向量数据库？")
print(response.answer)
print(response.sources)
```

### 自定义配置

```python
from rag_engine import RAGEngine, RAGConfig

config = RAGConfig(
    embedding_model="BAAI/bge-large-zh-v1.5",
    vector_store="milvus",
    chunk_size=500,
    chunk_overlap=50,
    top_k=5,
    temperature=0.7
)

rag = RAGEngine(config)

# 添加文档
rag.add_documents([
    {"content": "文档内容1", "metadata": {"source": "doc1.pdf"}},
    {"content": "文档内容2", "metadata": {"source": "doc2.pdf"}}
])

# 查询并返回来源
result = rag.query_with_sources("问题")
```

│                    文档准备最佳实践                          │
├─────────────────────────────────────────────────────────────┤

│  ❌ 避免过大：单个文档不要太大                               │

│                                                             │
└─────────────────────────────────────────────────────────────┘

### 2. 检索优化

```
优化技巧：

1. 查询优化
   - 查询扩展：添加同义词
   - 查询重写：优化查询表达
   - 多查询：生成多个相关查询

2. 索引优化
   - 选择合适的嵌入模型
   - 调整 chunk_size
   - 添加元数据过滤

3. 检索优化
   - 使用混合检索
   - 实施重排序
   - 调整 top_k 参数

4. 生成优化
   - 优化提示词模板
   - 添加引用要求
   - 控制输出格式
```

### 3. 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 检索不到相关内容 | 切分不当、嵌入质量差 | 优化切分、换嵌入模型 |
| 回答不相关 | 检索质量差、提示词不好 | 提高检索精度、优化提示词 |
| 回答幻觉 | 上下文不足 | 增加上下文、要求引用来源 |
| 响应慢 | 向量库性能差、检索慢 | 优化向量库、减少 top_k |
| 成本高 | 嵌入调用多、模型调用多 | 批量嵌入、缓存结果 |

## 小结

RAG 是解决大模型知识局限的核心技术：

- **原理**：检索相关文档 → 构建上下文 → LLM 生成
- **关键组件**：文档处理、嵌入、向量存储、检索
- **优化方向**：文档质量、检索精度、生成质量

掌握 RAG 是成为大模型应用工程师的必备技能。
